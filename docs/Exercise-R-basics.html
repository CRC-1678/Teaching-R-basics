Notes on R syntax

  • When you type R code, remember that R is case sensitive, so data is not the same as Data.

  • For most cases, it does not matter if you have a space between variable, operator and value, so 2+2 is the same as 2 + 2. It is recommended to use spaces for better code readability.

  • Single (’’) and double (““) quotes are equivalent in R, but pair them accordingly.

Variables assignment

In R (and other languages), variables are used to store values. In R, they don’t need to be declared in advance and are created at the moment when they are assigned a value. For example, we can assign number 3 to variable called x like that:

x <- 3

Some things to remember:

  • <- is preferred operator for assignment

    • Use Alt + - / Option + - shortcut for typing <-.

  • = operator can be used, but it is discouraged (some examples here).

  • Fun fact: -> assignment also works!

Variable names:

  • cannot start with a number
  • cannot contain - (will be evaluated as minus sign)
  • prefer not to contain spaces, use backticks if you must (`variable with space`)
  • should not overwrite built-in functions and variables names

Functions

Functions in R have a form of function(argument=value) (this is where = operator should be used). Functions perform some operations with their arguments and may or may not return a value. There are a number of built-in functions which are available in base R on startup (for example, you already saw print()). Many more functions are imported from packages (you already installed tidyverse package), and are available either after loading the package with library("package") or referencing the function like package::function().

To obtain help on how to call a function and all possible arguments, type ?function or help("function"). Tip: if you don’t remember the exact name, you can try apropos("approximate_name").

You can use ls() function to list variables and functions in your current environment. In RStudio, you can always find them in the “Environment” tab (in the top right quadrant by default):

ls()
## [1] "a" "b" "x"

To delete an unwanted variable or function, you can use function rm()

rm(a)
ls()
## [1] "b" "x"

You can create your own function in R using the following syntax: function <- function(argument=default_value){...}.

# By including  comment inside our function, we will help user to understand what it does
my_function <- function(x, y){
  print("Adding x and y")
  # This function will return the value of the sum of variables given
  return(x + y)
}

Note: if a function consists of one single statement, you can omit the curly brackets (even though it is recommended to use them for consistency):

my_short_function <- function(a) print(a)

Call our function:

a <- 42
b <- 123
my_function(a, b)
## [1] "Adding x and y"
## [1] 165

You can see the code of the function by calling its name without brackets:

# See the source code of the function
my_function
## function (x, y) 
## {
##     print("Adding x and y")
##     return(x + y)
## }

Calling it without an argument leads to an error:

my_function()
## [1] "Adding x and y"
## Error in my_function(): argument "x" is missing, with no default

A note on scope

You may have noticed that:

  • we have never introduced x and y before using them as arguments inside my_function definition and R did not complain that those variables were not found
  • then we have called our function on the variables a and b and R did not complain that it needs x and y as input

Like in many languages, R has global and local variables. Global variables can be accessed from anywhere in the code. Local variables are only valid for a specific part of the code (in our case, inside our function). When the function is called, its arguments are assigned to local variables x, y, and these local variables disappear after the function call is finished.

Indexing

Indexing means accessing element within a data structure (index refers to this element’s position).

R uses 1-based indexing (the first element is 1, not 0).

Use square brackets to access elements of a vector:

numbers <- 1:5
# Access elements
print(numbers[1])  # First element
## [1] 1
# Putting - in front of the index removes the element:
print(numbers[-2])
## [1] 1 3 4 5
# Using : operator returns the range of elements:
print(numbers[2:4])
## [1] 2 3 4
Subsetting

You can use conditional statements to select elements in a vector based on this condition:

numbers <- 1:10
numbers[numbers > 7]
## [1]  8  9 10
Type coercion

Vectors always contain the same data type. However, if you try to mix data types in a vector, R will not give you an error:

my_vector <- c(1,2,"3")
my_vector
## [1] "1" "2" "3"

You can see that instead R silently converted integers to characters! This is called type coercion and could lead to some unexpected behavior - see some more examples here.

Factors

factor in R represents specialized vector to encode categories. Implicitly, it takes a character vector, enumerates all types of words that occur in it, making categories (levels) and encodes the vector (internally) as integer with the numbers corresponding to categories.

# Create a factor
# Levels are sorted alphabetically be default
codons <- factor(c("ATG", "ATG", "AAG", "ATG", "AGG", "ATG"))
codons
## [1] ATG ATG AAG ATG AGG ATG
## Levels: AAG AGG ATG

Factors look very similar to character vectors but be aware that they behave differently. Later you will learn ggplot2 package - it coerces characters to factors for plotting. For modeling, factors are used to encode categorical variables. One useful function that uses factors is table() - it counts occurrences for each combination of categories.

codons <- factor(c("ATG", "ATG", "AAG", "ATG", "AGG", "ATG"))
table(codons)
## codons
## AAG AGG ATG 
##   1   1   4

Regular expressions

Regular expressions (or regex for short, check Wikipedia if you are not familiar with them) allow you to work with strings using patterns more complex than a simple exact match.

Here are main rules for regular expressions in R:

Pattern Meaning Example String Matches
. any character . "ATCG" “A”, “T”, “C” and “G”
[] any of the characters inside [AT] "ATCG" “A” and “T”
^ start of the string [^A] "AATAAA" only the first “A”
$ end of the string [T$] "AATAAA" no match
| matches one or the other expression [A|C] "AATAAA" matches all “A”
* zero or more of the expression A* c("GC", "TT", "AG") matches all three
+ one or more of the expression A+ c("GC", "TT", "AG") matches only “AG”
\\ “escapes” special character for literal match \\+ "23 + 45" matches “+”

Data frames

Data.frames are 2-dimensional (rows and columns) and can combine multiple types across a row, but each column must be of the same type. Essentially, a data.frame can be seen as a list of columns, each column being a vector of a single type.

Let us create a data frame which simulates biological data, for example, log fold changes of gene expression.

# Set seed for pseudorandom generator to get reproducible numbers
set.seed(42)

# How many genes
n <- 1000

# Simulate log fold changes from a normal distribution
logFC <- rnorm(n, mean=0, sd=1)

# Simulate p-values (uniform distribution by default between 0 and 1)
p_value <- runif(n)

# Create a vector of gene names (see below for operators on character vectors)
gene_names <- paste0("Gene_", 1:1000)

# Create a data frame by listing the columns
df <- data.frame(
  gene_name = gene_names
  , logFC = logFC
  , p_value = p_value
)

# Functions to peek into first/last few rows
head(df)
tail(df)
# Access column 
df[,"gene_name"][1:5]# use indexing [1:5] or head() to avoid printing the whole column
## [1] "Gene_1" "Gene_2" "Gene_3" "Gene_4" "Gene_5"
# Access row
df[1, ]  # first row

Note: with lists and data.frames (but not with vectors, matrices and arrays), you can use $ notation to access elements by name. In case of data.frames, you can you it to access a column like data.frame$column_name. If you get an error $ operator is invalid for atomic vectors, that means that you tried to use it on a data structure which is not a list (or a data.frame).

df$gene_name[1:5]
## [1] "Gene_1" "Gene_2" "Gene_3" "Gene_4" "Gene_5"

# Is expected gene in our table?

Note on vector recycling

If you try to create a data.frame using vectors of different length, R will not complain, and also not fill in missing values of the shorter vector with NA. Instead, it will recycle the shorter vector to fill in missing values, which could lead to unexpected results later. If however the longer vector’s length is not a multiple of shorter vector’s length, R will return an error:

# no warning, x is recycled
print(data.frame(x = 1:2, y = 1:6))
##   x y
## 1 1 1
## 2 2 2
## 3 1 3
## 4 2 4
## 5 1 5
## 6 2 6
# however, error if it cannot fit exact number of times
print(data.frame(x = 1:2, y = 1:5))
## Error in data.frame(x = 1:2, y = 1:5): arguments imply differing number of rows: 2, 5

We can also make use of vector recycling here to extend our data to simulate GO terms. We can simply add a new column like this:

df$GO_term <- c("neuronal", "immune") #no need to specify 1000 values

Note on missing values

As you remember, NA stands for missing value and can be of any type, so vectors (and also, lists, arrays and data.frame columns) can contain NA. One needs to be aware that NA could propagate silently, because any operation involving NA will return NA. Use na.rm=TRUE argument to ignore missing values:

# Introduce missing values into our data
set.seed(42)
# randomly select 10 rows where NA will be introduced
na_index <- sample(n, 10)
# set log2FC and p value to NA for these rows
df[na_index, c("log2FC", "p_value")] <- NA

# How many NA values are in the data?
sum(is.na(df$gene_name))
## [1] 0
# Calculate mean with missing values
mean(df$log2FC)  # Returns NA
## [1] NA
mean(df$log2FC, na.rm = TRUE)  # Returns a number
## [1] -0.02499976

Boxplot function

Boxplots are often used to visualise the distribution of numeric values between categories.

In base R, boxplot uses the so-called formula notation expressed by the tilde ~ operator. You will also encounter this notation in linear models, for example. In our case, it will have the form of value ~ category such as:

# plot a boxplot - group by categorical variable (for example, GO term)

boxplot(log2FC ~ GO_term
        , data = df
        , ylab = "Fold change"
        , col = c("blue","skyblue")
        )

Control flow

Control flow in programming allows you to execute commands based on a condition (if and while loops) and also to execute the same command on each element of many (for loops and apply functions).

Conditions

Conditions have a form of:

if (condition) {
  perform action
}

If a condition evaluates to TRUE, the command under if is executed, otherwise it is not, or a different command (under else) is executed, if provided.

# Simple example of an if-else condition statements
# Try changing the value of x and see what happens
x <- 5
if (x == 5) {
  print("Correct!")
} else {
  print("Wrong!")
}
## [1] "Correct!"

Loops

Loops allow you to write a command once instead of repeating it for each element you want to execute it on. A simple loop in R has a form of:

for (element in vector) {
  perform action (element)
}
#  for example, we take a squre root (built-in sqrt() function)
# from the grade from our students dataframe
for(gene in c("Gene_10", "Gene_100")){
  print(df[gene, ])
}
##             log2FC   p_value GO_term
## Gene_10 -0.0627141 0.3637062  immune
##             log2FC   p_value GO_term
## Gene_100 0.6532043 0.4966992  immune

Often, for loops in base R are replaced by a family of apply functions. The generic apply function has a form of apply(X, MARGIN, FUNCTION) where X is the data structure (can also be a matrix or array), MARGIN specifies dimensions to which we want to apply the FUNCTION (for example, 1 means rows, 2 means columns if X is a matrix). The syntax of apply is not very intuitive, but we can practice one often used lapply(X, FUN) function which performs operation on all elements of a vector or a list:

# lapply applies function to a vector/list
# lapply always returns a list
lapply(c("Gene_10", "Gene_100"), toupper)
## [[1]]
## [1] "GENE_10"
## 
## [[2]]
## [1] "GENE_100"

Some more information on the apply family and many examples can be found here.

Anonymous functions

If there is no existing function to use in apply, you can create a function directly on the spot (this is sometimes called anonymous function). This function is not assigned to any name and only exists during the call. The syntax for anonymous function can be written fully function(x) { do_something with x} or shortened to \(x) do_something with x, for example \(x) x+1 will add 1 to its argument. Instead of x you can use any name for the argument of the anonymous function (often a dot . is used).

logplus <- lapply(df$log2FC, function(x) x+1)

Vectorized operations

Vectorized functions in R can perform operations on all elements of a vector at the same time, avoiding use of for loop and apply. Those are very effective, and if possible, it is better to use them instead of loops. Many built-in R functions such as arithmetic operators, log() and similar perform vectorized operations if given vectors as arguments.

# Vectorized function returns a vector
exp(df$log2FC[1:5])
## [1] 3.9391243 0.5685317 1.4378205 1.8829931 1.4982059

Vectorized conditions

ifelse() is a vectorized form of if if you provide a a vector of mixed TRUE and FALSE as a condition. It has a form of ifelse(condition_vector, action1, action2), where action1 is performed if the condition in TRUE and action2 if the condition is FALSE.

ifelse(df$p_value < 0.02, "significant", "not significant")[1:5]
## [1] "not significant" "not significant" "significant"     "not significant"
## [5] "not significant"

Pipe

Pipe is an operator to direct a variable or a result of a statement into a next statement, allowing to chain several statements after each other. The pipe of the form %>% comes with the tidyverse package, however, base R has a built-in pipe of the form |> (since R 4.0). Mainly the pipe serves to make your code more readable and allows to better break it over several lines:

# instead of nesting functions like log(sum(sqrt(df$log2FC))), you can write:
df$log2FC |>
  sqrt() |>
  sum() |>
  log()
## Warning in sqrt(df$log2FC): NaNs produced
## [1] NaN

Base pipe always has to redirect to a function, and the name of the function has to be followed by brackets. If an anonymous function is used, the whole expression has to be put into brackets again, which makes the syntax (honestly) unreadable.

Luckily, you will learn tidyverse pipe operator %>% in the next class which handles it much better.

# Anonymous function has to be put into brackets, followed by another brackets to signify it is a function
logplus1 <- df$log2FC |> (\(.) . + 1)()
logplus1[1:5]
## [1] 2.3709584 0.4353018 1.3631284 1.6328626 1.4042683
